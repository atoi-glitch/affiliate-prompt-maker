# ことのは — アフィリエイト投稿作成補助

商品情報と一言メモから、ChatGPTに貼り付ける完成プロンプトを生成する最小構成の静的Webアプリです。投稿文そのものは生成しません。外部ライブラリ、有料API、外部通信、ビルド、アカウント登録は不要です。

## 起動

`index.html`、`style.css`、`app.js`を同じフォルダに置き、`index.html`をブラウザで開きます。JavaScriptを有効にしてください。モジュールやfetchは使用していません。

ローカルサーバーで確認する場合（Python導入済み）：

```sh
python -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。

## 使い方

1. 商品名と一言メモ（必須）を入力します。URL・セールメモ・補足メモは任意です。
2. 使用状況・セール状況・ターゲット・投稿タイプ・PR表記を選択します。自由入力ターゲットを選んだ場合は対象の入力が必須です。
3. 「プロンプトを生成」で完成プロンプトを表示し、履歴を保存します。
4. 「コピー」でコピーし、自分でChatGPTへ貼り付けます。

Threadsは2ツリー、Instagramはキャプション、Reelは15〜30秒の台本向けの指示を生成します。「全部」は3媒体分を含みます。使用状況に沿った型の選択、体験の捏造禁止、誇大表現や医療・美容効果の断定回避を指示します。

## 履歴

- **編集**：フォームへ読み込み、生成ボタンで既存の履歴を上書きします。作成日時・投稿状況・投稿日を保持します。
- **再利用**：フォームへ読み込み、次の生成時に新しい履歴として保存します。
- **プロンプト再生成**：保存済みの商品情報から再生成します。履歴は増えません。
- **投稿状況・投稿日**：履歴内で変更すると即時保存します。投稿日は任意の手動入力で、状態変更による自動入力はしません。
- **削除**：確認後に対象履歴を削除します。
- **リセット**：フォーム・編集状態・生成結果を初期化します。保存済みの履歴は残ります。

生成後は同じ商品の編集状態になります。別の商品を追加する場合はリセットまたは再利用を使ってください。

LocalStorageのキーは `kotonoha.products.v1`。履歴は端末・ブラウザ・サイトの配信元ごとに保存されます。別端末への同期はありません。ブラウザのデータ消去で履歴も消えます。直接起動時の保存動作はブラウザに依存するため、継続利用はGitHub Pagesでの利用を推奨します。

壊れたJSONや形式が不正なデータを検知した場合は警告し、元データを上書きせず画面内だけで動作します。保存拒否・容量不足の場合も警告し、生成機能は継続できます。一時保存分は再読み込みで失われます。

コピーはClipboard APIを優先し、利用できなければ選択コピーへ切り替えます。両方利用できない場合は文章を選択して手動コピーする案内を表示します。

PR表記は初期状態でONです。OFFも選べますが、実際の投稿に必要な広告表記と商品情報・セール情報は公開前に確認してください。商品URLからの商品情報取得は行いません。

## GitHub Pagesで公開（無料・リポジトリ未作成の場合）

GitHub Freeの **Public（公開）リポジトリ** を使います。有料プラン、独自ドメイン、APIキーの購入は不要です。ソースコードとWebアプリは公開されますが、フォーム入力・履歴は各利用者のブラウザ内に保存され、リポジトリへ送信されません。

### 1. GitHubにログイン

[GitHub](https://github.com/)で無料アカウントを作成するか、既存アカウントでログインします。PCのブラウザで設定すると操作しやすいです。

### 2. リポジトリを作成

1. [新規リポジトリ作成画面](https://github.com/new)を開きます。
2. **Repository name** に `affiliate-prompt-maker` と入力します。
3. **Public** を選択します。
4. **Add a README file** をONにします。後でこのアプリのREADMEに置き換えます。
5. **Create repository** を押します。

### 3. 4ファイルをアップロード

1. 作成したリポジトリの **Code** タブを開きます。
2. **Add file → Upload files** を選択します。
3. 次の4ファイルをまとめてドラッグ＆ドロップします。フォルダごとではなく、ファイル自体をアップロードしてください。

```text
リポジトリのルート（Codeタブを開いた直後の場所）
├── index.html
├── style.css
├── app.js
└── README.md
```

4. **Commit changes** を押して保存します。選択肢が出た場合は `main` ブランチへの直接コミットを選びます。
5. Codeタブの一覧に上記4ファイルが直接表示されることを確認します。`index.html` が別フォルダの中にあると、次の設定ではトップページが表示されません。

### 4. GitHub Pagesを有効にする

1. リポジトリの **Settings** を開きます。
2. 左側メニューの **Pages** を選びます。
3. **Build and deployment → Source** を **Deploy from a branch** にします。
4. **Branch** を `main`、フォルダを **/(root)** にして **Save** を押します。
5. 数分待ってPages画面を再読み込みします。**Your site is live at …** に表示されたURLを開きます。処理状況は **Actions** タブでも確認できます。

公開URLの例（`YOUR-USERNAME` は自分のGitHubユーザー名）：

```text
https://YOUR-USERNAME.github.io/affiliate-prompt-maker/
```

HTMLのCSS・JavaScript参照は `./style.css` と `./app.js` なので、このサブパスのURLでもそのまま表示できます。アプリ側のビルドやnpmインストール、独自のGitHub Actions設定は不要です。GitHub Pages側の配信処理は自動で実行されます。

### 5. iPhone Safariで確認

1. 公開された **https://** のURLをSafariで開きます（GitHubのファイル閲覧ページではありません）。
2. 商品名と一言メモを入力し、プロンプトを生成します。
3. **コピー** を押し、「メモ」などへ貼り付けて内容を確認します。自動コピーできない場合は結果欄を長押しして手動コピーします。
4. Safariでページを再読み込みし、履歴が残ることを確認します。
5. 履歴の編集・投稿状況変更・削除を試します。

通常のSafariタブで利用してください。プライベートブラウズや保存制限、サイトデータの削除では履歴が保持されない場合があります。ローカルで保存した履歴は、公開サイトには自動移行されません。

iPhone向けにviewport・セーフエリア、大きい操作ボタン、入力文字サイズ16pxを設定し、標準のフォーム・LocalStorage・Clipboard API（手動コピーへのフォールバックあり）を使用しています。最新のiOS Safariを想定した構成ですが、実機検証は未実施です。

### 表示されない場合

- **404**：公開処理の完了、`main` / `/(root)` の指定、ルートの小文字 `index.html` を確認します。
- **見た目が崩れる／生成できない**：`style.css` と `app.js` が `index.html` と同じ場所にあること、ファイル名の大文字・小文字を確認します。
- **更新が反映されない**：Actionsの完了を待ち、ページを再読み込みします。履歴を残したい場合はサイトデータを消去しないでください。

### 後から更新する場合

Codeタブの **Add file → Upload files** から変更したファイルを同じ名前・同じ場所にアップロードし、Commit changesで保存します。公開処理の完了後、同じURLに反映されます。

## 動作確認

GitHub Pages準備時には `/affiliate-prompt-maker/` のサブパス配信をローカルで再現し、CSS・JavaScript読み込み、プロンプト生成、再読み込み後の履歴保持、390px幅での表示を追加確認しました。外部への通信とJavaScriptエラーはありませんでした。実際のGitHub Pagesへのアップロード・公開はまだ行っていません。

2026-10-17、ローカルHTTPサーバー＋Chromium（Playwrightによるブラウザ操作）で以下を確認しました。

- 必須項目、自由入力ターゲットのエラー表示
- 3媒体すべてのプロンプト生成、入力値の反映、PR OFF
- コピーボタンの成功表示（Clipboard API利用不可時のフォールバック）
- 履歴保存・再読み込み後の保持
- 編集・削除・再利用・履歴からの再生成
- 投稿状況・投稿日変更と再読み込み後の保持
- リセット
- 壊れたLocalStorageでも生成でき、破損した元データを上書きしないこと
- 320 / 375 / 390 / 768 / 1280px幅で横方向にはみ出さないこと
- 操作中のJavaScriptエラーなし
- `node --check app.js` による構文確認

実行環境のChromium管理ポリシーが `file://` を禁止していたため、**index.html直接起動のブラウザ実測は未完了**です。実装は直接起動可能な通常のscript/CSS参照だけで構成しています。iPhone Safari実機と実際のGitHub Pages公開後の確認は未実施です。
